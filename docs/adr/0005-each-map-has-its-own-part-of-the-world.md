> Superseded by [ADR 0009](0009-every-map-is-built-at-the-world-origin.md): every Map is now built centred on the world origin, and `zone_at` and the other position lookups take the current Map. The rest of this ADR (one `ZoneId` enum whose variants know their Map, one `WINDOWS` table, per-Map systems reading the current `Layout`) stands.

# Each Map is built in its own part of the world, and its Zones and windows are unique to it

A Map is a `Layout` of data chosen by `MapId`: its Zones, windows, Spawn Points, floors, Props and path nodes. The spots of things a system owns (the Perk machines, the Power Switch, Pack-a-Punch, the Traps, the Equipment walls) stay with that system, looked up by `MapId`. Rather than make `ZoneId` and `BarrierId` mean different things on different Maps, every Map's Zones are variants of the one `ZoneId` (each knows its Map), every Map's windows sit in one `WINDOWS` table so a `BarrierId` names one window on one Map, and every Map is built in its own patch of the world (the Quarry `QUARRY_X` along x, the Village `VILLAGE_X`, the Dam `DAM_X`), so no two Maps' Zone volumes overlap. That keeps `zone_at`, Zone tracking, the window and Barrier code and everything sent over the network free of any notion of the current Map: a point, a Zone or a Barrier already says which Map it belongs to. Only what's spawned, and the path-node graph, are picked by the `MapId` resource when a Run starts. Jump Pads are the exception that proves the rule: they're floor the Map is built with, and the movement step reads them as a Map's geometry, so they live in its `Layout`. So do the Sections and their Zones, the Generators, whether the Map has Darkness, and when its Sappers come (its `SapperTiming`): each is read by one generic system (Generators, Surge, Darkness, the Sapper) from whichever Map's `Layout` is current, the way Jump Pads are, and a Map with Generators has no Power Switch.

We chose this over a per-Map `ZoneId` (a generic or a trait per Map) because about thirty modules reach Zones, windows and Barriers through free functions and plain data, and threading the current Map through each would have touched most of the game for no gain in behaviour. The cost is that `ZoneId` grows with every Map, `ZoneSet` is a bit set wide enough for all of them, and a new Map must be placed clear of the others; `every_map_keeps_to_its_own_part_of_the_world` checks it. Decided in [Introduce a second Map](https://github.com/jchevertonwynne/zombies/issues/105).
