# Zombies navigate a hand-authored path-node graph, not a navmesh

Zombies plan with A* (the `pathfinding` crate) over a graph of about 40 path nodes and edges listed by hand in the Map data. Each edge is tagged with what gates it: a Door, a Barrier or a one-way drop. We chose this over a navmesh because every navmesh crate (vleue_navigator, landmass, rerecast) still targets Bevy 0.19 and avian 0.7. `bevy_flowfield_tiles_plugin` supports Bevy 0.20 but handles only one floor, and the Map has a Balcony. A hand-authored graph also matches how BO1 did it, with placed path nodes and Doors connecting the paths, so it carries no dependency risk. The cost is that every new Map needs its nodes placed by hand. Decided in [Zombie navigation and Barrier entry](https://github.com/jchevertonwynne/zombies/issues/6).

> Amended by [ADR 0011](0011-maps-are-data-files.md): the graph is now generated from each Map File's Footprints and Walls, with hand edits pinned on top, rather than listed by hand. It is still a graph searched with A*, not a navmesh.
